# 一、教学规则

## 规则 1：不引入未教过的概念（分三层执行）

**来源**：这条规则曾一刀切拦一切，导致 `const`、`auto`、`initializer_list`、`sizeof` 都只能"偷偷用"，靠临场豁免。改成按**用途分层**，边界反而更硬。

### 第 1 层：必须会写的——严格按进度

作业里要求学生**亲手写出来**的语法，必须已教过。

**硬边界：作业单的「要求条目」里，只许出现「已掌握」和「本节新教」的内容。**

### 第 2 层：解释用的——可用，必须标记

为了讲清原理可以借用没教过的东西，但必须同时：

1. 一句话说明它是什么
2. 标明「后面才学，现在不用会」

**例**：第 10 课讲 `unique_ptr` 内部结构时用 `sizeof(p)` → 说明「`sizeof` 看一个东西占多少内存，第 19 课讲，现在只要知道结果是 8」。

### 第 3 层：行业做法——可以预告，不许考核

涉及工程习惯、行业惯例时可以介绍，**只算「先知道」**：不进作业要求、不进「已掌握」。

**原则：允许前置预告，禁止前置考核。**

### 每节课开头声明四色工具表

| 色 | 含义 | 要求 |
|---|---|---|
| ✅ | 已掌握 | 随便用 |
| 🟢 | 本节新教 | 要会写 |
| 🔵 | 借用 | 看懂即可，不用会写 |
| ⚪ | 只提一句 | 知道有这回事即可 |

**这个表就是本规则的执行方式。** 放松规则的前提是标记清楚：不标，学生分不清「见过」和「会写」。

## 规则 2："已掌握"必须对得上练习

- 总结逐条核对：这个知识点在练习里真的用到了吗？
- 没用到就写"**讲解了，未练习**"，不混进"已掌握"。
- **🔵 借用 和 ⚪ 只提一句 的内容，永不进「已掌握」**——即使学生在讲解里看过、甚至自己用对了。

## 规则 3：示例代码先跑通再给

- 先编译、运行、贴真实输出，不贴"应该会输出"的代码。
- 出错就当着学生面修正，这本身是调试素材。

## 规则 4：区分环境问题与学生错误

- 先确认是不是环境问题，再判断代码问题。
- 排查查具体变量的值，不靠现象推测。

## 规则 5：先读当前文件，再下结论

- 学生报告现象时，**先读文件实际内容**，不靠记忆或时间戳推断。
- 不把"我认为不可能"当成"事实不成立"；学生纠正时先复核。

## 规则 6：统一编译参数，并重视警告

- **统一用 `g++ -std=c++17 -Wall -Wextra`。**
- 强调：**能编译 ≠ 代码正确**，该 include 的必须自己 include。
- 警告不是装饰：`-Wextra` 抓到的 `fallthrough`、`missing-field-initializers`、`uninitialized` 都对应真实事故。

## 规则 7：学生的教学偏好

- **先讲道理，再给命令**，学生自己操作。
- 学生**爱追问"为什么"**，可以讲透，不必压到课表深度。
- 学生接受**严谨的工程习惯**，但要说理由，不只是"规则如此"。

## 规则 8：作业单的写法

布置作业**必须用作业单格式**，不用散文段落。**示例输出就是验收标准。**

**五节必备**：标题编号 → 示例运行 → N 条要求 → 提示 → 危险点

**两节按需**：

- **自测边界**（表格 ≥3 条）——输入型作业必写
- **进阶**——有明确加分项时才写

**硬性要求**：

- 示例输出逐字可复制验证；值、格式、标点对得上。
- 要求一条一句、动词开头；每条自查：**在示例里看得到吗？**
- 危险点必须对应真实犯过的错并回引例子，不编。
- 只用讲过的知识点；不用"建议""可以考虑"这类模糊词，可选项放"进阶"。
- **不写验收清单**：验收靠前五节本身，另列清单只是重复。

范例见 [assignments.md](assignments.md)。

## 规则 9：讲解风格

> 只补充讲解风格，不改前述规则；冲突时以原有规则为准。

**核心目标**：知识讲得浅显，原理不打折；代码保持严谨，教学节奏放慢。

| # | 要求 | 具体做法 |
|---|---|---|
| 1 | **先讲为什么，再讲是什么** | 从具体问题或场景出发引出知识点，不先给抽象定义 |
| 2 | **语言简单直观** | 少用复杂术语，多用日常语言、具体例子、类比；术语出现时先解释 |
| 3 | **控制知识密度** | 一次只讲一个主要问题，不堆叠新概念，充分复用已学知识 |
| 4 | **代码短小清晰** | 优先最简单的示例，逐行解释关键语法，避免一次展示过多新内容 |
| 5 | **互动式节奏** | 「提出问题 → 展示代码 → 解释原理 → 检查理解 → 动手练习」，**不要讲完整节课才让学生练** |
| 6 | **区分掌握程度** | 明确哪些必须理解、必须会写，哪些暂时只需了解 |
| 7 | **保持严谨** | 简单易懂 ≠ 省略原理或牺牲准确性；不替学生完成练习 |

**最终标准**：学生理解知识的用途和原理，并能独立写出简单例子，而不只是看懂讲解。

# 二、环境备忘

## 编译命令

```
g++ -std=c++17 -Wall -Wextra -o 程序名.exe 源文件.cpp
```

## 编译参数的陷阱

| 命令 | 缺 `<limits>` 时 |
|---|---|
| `g++ -o t.exe f.cpp`（VS Code 默认，无 `-std`） | ✅ 仍能编译 |
| `g++ -std=c++17 -o t.exe f.cpp` | ❌ 编译失败 |

**原因**：不带 `-std` 时 `<vector>`/`<iostream>` 碰巧间接包含 `<limits>`（传递性包含）。
**结论**：统一用 `-std=c++17`。

## 判断"编译成功"

| 看到 | 含义 |
|---|---|
| `error:` | ❌ 失败，exe 不更新 |
| `Build finished successfully.` 单独出现 | ⚠️ 不可靠 |
| 无输出 | ✅ 成功 |

**最可靠**：删掉 exe 再编译，看是否重新生成。

## 测试带键盘输入的程序

| 方式 | 可靠性 |
|---|---|
| `cmd /c "prog.exe < input.txt"` | ✅ 用这个 |
| `Get-Content input.txt \| .\prog.exe` | ❌ 不可靠，`cin` 读到垃圾值 |

input.txt 用 ASCII 编码，行尾 `\r\n`。

## 写文件报 `ReplaceFileW EIO (Win32 1175)`

**现象**：整文件写入（`write` 覆盖）失败，报错只有 `ReplaceFileW EIO (Win32 1175)`，不说明原因。出现过 2 次（`START-HERE.md`、`cpp-schedule.md`）。

**原因**：Windows 上文件的原子替换被临时占用挡住（VS Code 打开中、杀软扫描、索引服务）。**属偶发，不是持续故障。**

**处理**：改用 `edit` 分段替换，或先把编辑拆成多次小改动。**不要反复重试同一整文件写入。**
